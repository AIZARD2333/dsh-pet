# 干活模式（pet work）

桌宠的对话默认只是一次 LLM 闲聊。这个分支加了一条「真干活」的路：把一句话交给一个**真正的 DSH agent 会话**，带工具、带工作区，跑完把结果说回给你。

## 怎么用

在桌宠对话窗口里，消息以 `!`、`！` 或 `/work` 开头就是干活：

```
!把 README 里的错字改掉，改完跑一遍测试
！看看 logs 里今天最大的那个日志报了什么错
/work 把 src/host 下所有 TODO 列出来
```

- **立刻回执**：宠物先说「收到，本鱼去干活了。干完喊你。」（客户端 60 秒超时，等不起一整轮工作，所以先回执）
- **干完回报**：一轮结束后，结果写进宠物气泡，同时记进对话记忆；下一轮接着聊会带上这段历史
- **一个宠物一条会话**：同一个宠物的多次干活共享上下文，可以直接说「接着刚才那个继续」
- **同一只宠物同时只跑一件**：上一件没结束时再发，会回「上一件还没干完」

## 它在哪干活

- 默认工作区：`~/.dsh/pet-work`（Windows 是 `%USERPROFILE%\.dsh\pet-work`），不存在会自动建
- 想换目录：启动 DSH 前设置环境变量 `DSH_PET_WORK_CWD` 为绝对路径
- 会话 id：`pet-work-<宠物 id>`，在 DSH 的会话列表里能看到

## ⚠️ 权限：完全访问，没有审批

桌宠没有审批界面。如果干活会话按默认权限跑，遇到要确认的命令就会**一直等到超时**，所以插件会把这条会话设成 `danger-full-access`（完全访问）：

- 它能读写整个磁盘、跑任意命令，**不会问你要不要允许**
- 只把这个模式交给你自己；别把它接到不可信的输入源上
- 不想要这个行为，就别用 `!` 前缀——普通的桌宠对话仍然是安全的单次 LLM 调用

## 限制

- 单轮最多 **20 分钟**，超时会中止并回报「干太久了」
- **暂不支持图片**：带图会拒绝，建议把图放进工作区再告诉它路径
- **独立模式不可用**：没有 DSH 会话服务时，`!` 会返回「当前环境没有会话服务」
- 回复正文超过 4000 字时，气泡只显示前 4000 字，完整正文仍在对话记忆里

## 实现位置

- `src/host/pet-work.ts`：会话创建、`agent/assistant-stream` 收流、超时与并发控制
- `src/host/plugin/chat-memory.ts`：识别触发前缀、回执、完成后写气泡与记忆
- `src/host/pet-work.test.ts`：不依赖 DSH 运行时的自检

## 自检

```sh
node --experimental-strip-types --test --test-isolation=none src/host/pet-work.test.ts
```
